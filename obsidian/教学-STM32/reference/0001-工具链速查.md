# 0001 · 工具链速查（STM32 课程）

> 配套 [[../lessons/0001-工具链闭环与LED闪烁|Lesson 0001]]。命令可复制，报错对照表贴查找。

## 一、安装命令

### WSL（Ubuntu）

```bash
sudo apt update && sudo add-apt-repository universe && sudo apt update
sudo apt install -y gcc-arm-none-eabi cmake stlink-tools openocd usbip
```

### Windows（管理员 PowerShell）

```powershell
winget install --id dorssel.usbipd-win
code --install-extension ms-vscode.cpptools
code --install-extension ms-vscode.cmake-tools
code --install-extension marus25.cortex-debug
code --install-extension ms-vscode.vscode-serial-monitor
```

浏览器安装（ST 官网，需账号）：STM32CubeMX / STM32CubeProgrammer（含 ST-Link 驱动）。

## 二、日常命令

```bash
# 编译（vscode CMake Tools 一键，或命令行）
cmake -S . -B build && cmake --build build

# 烧录（.bin → 0x8000000）
st-flash write build/<name>.bin 0x8000000

# 查看烧录器是否识别
st-flash --version        # 列出 1 个 STLink
lsusb                     # 看到 0483:3748 = ST-Link V2

# usbipd 日常（拔插 USB 后需要重挂）
sudo usbip detach -p <port> && sudo usbip attach -w -b <busid>
```

## 三、常见报错对照

| 报错/现象 | 原因 | 解决 |
|---|---|---|
| `usbip: error: version mismatch` | WSL 内核与 linux-tools 版本不一致 | `sudo apt install linux-tools-generic`；仍不行先跳过 |
| `st-flash: error: could not connect to stlink` | USB 未挂载 / interface 没 bind 全 / 驱动问题 | `lsusb` 查设备；重新 bind/attach；Windows 装 ST-Link 驱动 |
| `st-flash: error: failed to open device` | ST-Link 复合设备只 bind 了 1 个 interface | `usbipd bind` 补上另一个 busid |
| 烧录成功但灯不闪 | 供电不足 / 接线松 / 没复位 | 检查 3.3V+GND、RESET 按键 |
| CMake 找不到 kit | 编译器路径未注册 | 指定 `arm-none-eabi-gcc` 全路径或装 C/C++ 扩展 |
| CubeMX 生成工程报路径错 | 路径含中文/空格 | 工程名用纯英文 |
| 重新生成后手改代码消失 | 改在了 USER CODE 区外 | 业务代码必须写在 `USER CODE BEGIN/END` 之间 |
| 调试器再也连不上芯片 | 程序占用了 PA13/PA14 | CubeMX 里 SYS→Debug→Serial Wire 必须先开；已锁死需 BOOT0 拉高 ISP 恢复 |

## 四、关键地址与常量

| 项 | 值 | 说明 |
|---|---|---|
| Flash 起始地址 | `0x8000000` | 上电取指地址，烧录目标 |
| 板载晶振 | 8MHz（HSE） | PLL×9 = 72MHz 主频 |
| 板载 LED | PC13（低电平亮） | 部分板子在 PA1，看丝印 |
| ST-Link VID | `0483:3748` | `lsusb` 识别用 |

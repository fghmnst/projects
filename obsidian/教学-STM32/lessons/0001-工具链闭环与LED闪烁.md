## 二、芯片内部模型与三层抽象

### 1. 一块芯片里有什么

STM32F103C8T6 不只是"一个 CPU"，它内部是一个完整的微型电脑：

| 部件 | 容量/规格 | 类比 | 存什么 |
|---|---|---|---|
| **内核 CPU** | ARM Cortex-M3 @ 72MHz | 大脑 | 执行指令 |
| **Flash** | 64KB | 硬盘（U盘） | 你的程序代码，**掉电不丢** |
| **RAM** | 20KB | 内存 | 运行中的变量，掉电清空 |
| **外设** | GPIO/TIM/UART/... | 感官与肌肉 | 看、听、输出、计时 |
| **总线** | 内部互联 | 神经 | CPU 与外设之间传数据 |

> [!note] 术语
> **MCU（Microcontroller Unit，微控制器）**：一块芯片集成了 CPU+存储+外设的完整微型计算机。STM32 是 ST 公司的 MCU 系列，**F103C8T6** 是具体型号：Cortex-M3 内核、64KB Flash、LQFP48 封装。
> **外设（peripheral）**：芯片内部除了 CPU 和存储以外的功能模块。GPIO（通用输入输出）是"手"，UART 是"嘴"，定时器是"节拍器"。

### 2. 时钟树：一切动作的心跳

芯片里所有模块的运转都靠一个统一的**节拍器**——时钟。晶体（晶振）提供基础节拍（板载 8MHz），通过内部**PLL（锁相环，倍频器）**乘到 72MHz 给 CPU 用。

**时钟树（clock tree）**就是"时钟信号怎么从晶振分给各个模块"的配置图。CubeMX 里有一整页图形化配置，本课只需记住：**F103 的经典配置 = 8MHz 晶振 × PLL9 倍频 = 72MHz 主频**。

### 3. 三层抽象：寄存器 → HAL → 应用代码

控制 LED 灯（GPIO）这件事，可以用三种粗细不同的方式写：

```c
// 第 1 层：寄存器（直接写硬件地址）——底层、难读、容易错
GPIOA->ODR = 0x0001;                    // 直接操作内存映射的寄存器

// 第 2 层：HAL 库（ST 官方封装）——好读、好用，本项目全用它
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_0, GPIO_PIN_SET);

// 第 3 层：应用代码（你写的业务逻辑）
void led_on(void) { HAL_GPIO_WritePin(LED_PIN, GPIO_PIN_SET); }
```

> [!note] 术语
> **寄存器（register）**：CPU/外设里可读写的特殊存储单元，通过内存地址访问，是硬件的最小操作单位。`GPIOA->ODR` 就是"GPIOA 组的输出数据寄存器"。
> **HAL 库（Hardware Abstraction Layer，硬件抽象层）**：ST 官方把寄存器操作封装成的 C 函数库。教学选它的理由：先学会"调函数"，不被底层细节淹没；将来需要时随时可以下钻到寄存器。

### 4. CubeMX 为什么存在

手写初始化代码（配时钟、配 GPIO 模式）极其繁琐且容易错。**CubeMX** 是 ST 官方图形化配置工具：你勾选外设、画时钟树，它自动生成全部初始化代码。

- **`.ioc` 文件**：工程配置档案（纯文本），记录你勾选的一切。改配置 = 改 .ioc 再重新生成代码。
- **USER CODE 区**：生成的代码中有 `/* USER CODE BEGIN xxx */ ... /* USER CODE END xxx */` 保护区间，你手写的业务代码放这里，**重新生成时不会被覆盖**。CubeMX 生成器在 USER CODE 区外的手改内容会被冲掉。

## 三、工具链全景：每个工具是什么、为什么选、会踩什么坑

**工具链（toolchain）**：从源码到运行所需的一整套工具（编译器+构建系统+烧录器+...）。

| 工具 | 作用 | 为什么选 | 可能遇到的问题 |
|---|---|---|---|
| **arm-none-eabi-gcc** | 把 C 源码编译成 ARM 机器码（.elf/.bin） | 免费开源、嵌入式事实标准；参考仓库和 ST 官方都用它 | 版本与链接脚本偶有不兼容；首次链接报缺库 |
| **CMake** | 构建系统：管理"怎么编译"，生成构建文件 | CubeMX 原生输出 CMake 工程；vscode 插件直连；参考仓库已是 CMake 工程 | 首次要选 preset；改了 CMakeLists.txt 忘重新 configure |
| **stlink-tools**（st-flash） | 命令行烧录：把 .bin 经 ST-Link 写入 Flash | 一条命令烧录；WSL 里直接跑（配合 usbipd）；本项目烧录主力 | 与 ST-Link 固件版本兼容性；烧完灯不闪多半是接线/供电 |
| **openocd** | 开源调试器：断点、单步、看变量；也能烧录 | Cortex-Debug 插件的后端，后续调试 PID 时用 | 配置脚本参数错误；与 st-flash 同时占用设备会冲突 |
| **usbip**（WSL 端） | 接收 Windows 共享的 USB（ST-Link），让 WSL 能烧录 | 唯一官方推荐的 WSL2 USB 直通方式；编译烧录同一环境 | 内核版本不匹配报错；需 root；拔插后失效要重 attach；ST-Link 双 interface |
| **STM32CubeMX**（Windows GUI） | 图形化配置芯片与外设，生成初始化工程 | ST 官方、教学最友好；参考仓库 .ioc 同流程 | 首次要下载固件包 STM32CubeF1；路径含中文/空格出错；重生成覆盖 USER CODE 外的手改 |
| **STM32CubeProgrammer** | 官方烧录/调试软件，附带 ST-Link 驱动 | 官方最可靠；同时是 Plan B 烧录通路（Windows 侧 CLI） | 旧驱动残留冲突；首次连不上多半是接线/供电 |
| **usbipd-win**（Windows） | 管理员服务：把 ST-Link 共享给 WSL | 微软官方推荐的 WSL 直通方案 | 需管理员；bind 首次装驱动；ST-Link 两个 interface 要分别 bind |
| **VS Code 插件 ×4** | C/C++（提示跳转）、CMake Tools（一键编译）、Cortex-Debug（图形化调试）、Serial Monitor（串口观察） | 覆盖编译→调试→串口全流程；vscode 路线已定 | CMake Tools 首次要选 kit/preset；Cortex-Debug 要配 launch.json |

### 重点解释 1：交叉编译（cross-compile）

普通 gcc 编译出的程序只能在**本机**（x86）跑。而 STM32 是 ARM 架构，需要一种"在 x86 电脑上编译出 ARM 机器码"的编译器——这就是**交叉编译器**。

`arm-none-eabi-gcc` 名字拆解：
- **arm**：目标架构是 ARM
- **none**：无操作系统（bare-metal，裸机）——STM32 上没跑 Linux，程序直接跑在硬件上
- **eabi**：嵌入式应用二进制接口（Embedded Application Binary Interface）——规定函数调用、参数传递等规则的"约定"，编译器与链接器按同一套约定配合

> [!note] 术语
> **EABI**：嵌入式平台的 ABI（应用二进制接口）约定。简单记：编译器产出的代码和链接器/调试器能互相配合的"接头暗号"。

### 重点解释 2：构建系统 CMake

编译器是一个一个文件的翻译官，但工程有几十个源文件、还有头文件路径、链接脚本、宏定义——谁负责把这一切组织起来？**构建系统（build system）**。

- `CMakeLists.txt`：构建规则声明文件（哪些源文件、输出什么）
- `CMakePresets.json`：预设的构建配置（vscode 打开工程时会让你选）
- 流程：CMake 读取规则 → 生成 Makefile/ninja → 真正的编译由 make/ninja 执行

### 重点解释 3：烧录与 SWD

**烧录（flash）**：把编译产物 .bin/.elf 写入芯片的 Flash。编程的"编程"就是写 Flash。

**ST-Link V2** 是 ST 官方调试烧录器（一个小 USB 设备），通过 **SWD（Serial Wire Debug，串行线调试）** 协议连接芯片——只需 4 根线：

| ST-Link 引脚 | 接板子 |
|---|---|
| SWDIO (DIO) | 板上 SWDIO 排针（PA13） |
| SWCLK (CLK) | 板上 SWCLK 排针（PA14） |
| GND | GND |
| 3.3V | 3.3V |

> [!warning] 为什么必须配置 "Serial Wire" 调试口
> 芯片的 PA13/PA14 既是 SWD 调试口，也能当普通 GPIO。如果不先在 CubeMX 里把 Debug 配置为 Serial Wire，程序可能把这两个引脚改作他用，调试器就再也连不上芯片（只能 BOOT0 拉高进 ISP 恢复）。**任何工程第一步都先开 Serial Wire。**

### 重点解释 4：为什么 WSL 烧录要 usbipd

WSL2 是虚拟机，**默认访问不了 Windows 的 USB 设备**（ST-Link 插在 Windows 上）。usbipd-win 是微软官方方案：Windows 把 USB 设备"共享"出去，WSL 里用 usbip 客户端"挂载"进来。挂载后 WSL 里 `st-flash` 就能直接操作 ST-Link，编译与烧录都在同一环境。

> [!note] 术语
> **vhci**：虚拟主机控制器接口（Virtual Host Controller Interface）——usbipd 在 Windows 侧创建的"虚拟 USB 总线"，设备经它共享给 WSL。**busid**：USB 设备的端口标识（如 `3-2`），bind/attach 都要用它。
> **驱动（driver）**：操作系统与硬件之间的翻译层。ST-Link 要装 ST 官方驱动，Windows 才能识别它。

## 四、动手 1：安装工具链

### 步骤 1：WSL 内安装（复制粘贴）

```bash
# 1. 更新软件源（若提示 universe 仓库未启用，先启用）
sudo apt update
sudo add-apt-repository universe   # 已启用可跳过
sudo apt update

# 2. 安装编译工具链与烧录工具
sudo apt install -y gcc-arm-none-eabi cmake stlink-tools openocd usbip

# 3. 验证（期望：arm-none-eabi-gcc 13.x / cmake 3.x / st-flash 1.7.x）
arm-none-eabi-gcc --version | head -1
cmake --version | head -1
st-flash --version 2>&1 | head -1
```

> [!warning] 可能的坑
> `usbip` 报内核版本不匹配（WSL2 常见）：加装 `linux-tools-generic` 再试；仍不行先跳过（不影响编译，只影响步骤 3）。

### 步骤 2：Windows 侧（管理员 PowerShell）

```powershell
# 1. usbipd-win（USB 直通服务）
winget install --id dorssel.usbipd-win

# 2. VS Code 插件
code --install-extension ms-vscode.cpptools
code --install-extension ms-vscode.cmake-tools
code --install-extension marus25.cortex-debug
code --install-extension ms-vscode.vscode-serial-monitor

# 3. 验证
winget list usbipd
code --list-extensions | grep -iE "cpptools|cmake|cortex|serial"
```

```powershell
# 4. STM32CubeMX —— 浏览器下载安装（需注册 ST 账号）
#    https://www.st.com/en/development-tools/stm32cubemx.html
# 5. STM32CubeProgrammer（含 ST-Link 驱动）—— 浏览器下载安装
#    https://www.st.com/en/development-tools/stm32cubeprog.html
```

### 步骤 3：usbipd 直通（Windows ↔ WSL 协作）

```powershell
# Windows（管理员）：列出设备，找到 ST-Link（VID 0483）
usbipd list

# Windows（管理员）：绑定（ST-Link 常枚举为 2 个 interface，两个都要 bind）
usbipd bind --busid <busid-1>
usbipd bind --busid <busid-2>
```

```bash
# WSL：挂载（需 root）
sudo usbip attach -w -b <busid-1>
sudo usbip attach -w -b <busid-2>

# 验证：看到 0483:3748（ST-Link V2）即通路打通
lsusb
st-flash --version   # 列出 1 个 STLink 即成功
```

> [!warning] usbipd 的坑
> 1. 拔插 USB 后 WSL 连接失效：`sudo usbip detach -p <port>` 后重新 attach。
> 2. ST-Link 是复合设备（2 个 interface），漏 bind 任何一个，st-flash 都会报找不到设备。
> 3. 若 30 分钟搞不定：放弃 usbipd，告诉我，降级 Windows 侧 CubeProgrammer CLI（Plan B，永不阻塞）。

## 五、动手 2：CubeMX → 编译 → 烧录 → 蓝灯闪

### 步骤 1：CubeMX 生成工程

1. 打开 CubeMX → `New Project` → MCU Selector → 搜索 `STM32F103C8T6` → 选中（LQFP48）→ 开始项目
2. **先开调试口**：左侧 `System Core` → `SYS` → Debug 选 **Serial Wire**（PA13/PA14 锁定为 SWD，本课第二节警告过的）
3. **配时钟**：左侧 `System Core` → `RCC` → HSE 选 `Crystal/Ceramic Resonator`（板载 8MHz 晶振）；上方 `Clock Configuration` 页 → 输入 72 回车，点 OK（CubeMX 自动配好 PLL×9）
4. **配 LED 引脚**：在芯片图里点 **PC13** → 选 `GPIO_Output`（Blue Pill 板载 LED 接 PC13，低电平点亮；若你板子 LED 在别的引脚如 PA1，点对应引脚即可）。下方 `GPIO_Output Level` 保持 Low（开机即亮，方便验证）
5. 左侧 `Project Manager` → 填工程名（**纯英文无空格**，如 `led_blink`）、路径选 `~/projects/` 下，Toolchain/IDE 选 **CMake** → `Generate Code` → 打开工程

> [!note] 术语
> **代码生成（code generation）**：CubeMX 按 .ioc 配置自动生成 `main.c`、`stm32f1xx_hal_msp.c` 等初始化文件的过程。生成的 `MX_GPIO_Init()`、`SystemClock_Config()` 就是第二节说的"初始化代码"。

### 步骤 2：vscode 编译

1. vscode 打开生成的工程目录（`code ~/projects/led_blink`）
2. CMake Tools 会弹出：选择 **kit = GCC for arm-none-eabi**、preset 选默认（Debug）
3. 底部状态栏点 **Build**（或 `Ctrl+Shift+P` → `CMake: Build`）
4. 产物在 `build/` 下：`led_blink.elf` 和 `led_blink.bin`

> [!warning] 可能的坑
> 找不到 kit：确认 C/C++ 扩展装了 arm-none-eabi 的编译器路径；或手动指定 `arm-none-eabi-gcc` 全路径。

### 步骤 3：接线（断电操作）

| ST-Link V2 引脚 | 板子排针 |
|---|---|
| SWDIO | SWDIO (PA13) |
| SWCLK | SWCLK (PA14) |
| GND | GND |
| 3.3V | 3.3V |

板子 USB 插电脑供电（本课还没有舵机，USB 供电足够；**舵机必须独立 5V/2A 供电，这是后续课的坑**）。

### 步骤 4：烧录

```bash
cd ~/projects/led_blink
st-flash write build/led_blink.bin 0x8000000
```

看到 `Flash written and verified! jolly good!` 即成功。若末尾没带复位，按一下板子 RESET。

> [!note] 术语
> **0x8000000**：F103 的 Flash 起始地址。芯片一上电就从这里取第一条指令。**链接脚本（.ld 文件）**规定了程序各段放哪里——这就是为什么编译要带 `STM32F103XX_FLASH.ld`。

### 步骤 5：第一个"改码→看效果"闭环

1. 观察：板载 LED 应该以某频率闪烁（CubeMX 默认 main 循环里已有 `HAL_GPIO_TogglePin` + `HAL_Delay(1000)` 模板）
2. 打开 `Core/Src/main.c`，在 `/* USER CODE BEGIN 3 */` 与 `/* USER CODE END 3 */` 之间找到 while 循环
3. 把 `HAL_Delay(1000)` 改成 `HAL_Delay(200)` → 重新 Build → 重新烧录 → 观察闪烁变快
4. 换回 1000，再试 `500`——感受"改代码 → 编译 → 烧录"的完整循环，这就是你之后每天的日常

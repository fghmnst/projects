### 报错排查：`stm32f10x.h: No such file or directory` + main.c 重写
- **根因**：main.c 被改成 11 行且 `#include "stm32f10x.h"`——这是**标准外设库（SPL，老库）**的头，工程是 **HAL 库**（`stm32f1xx.h`/`stm32f1xx_hal.h`），工程内不存在 → fatal error
- **重写为 HAL 最小点灯程序**（PA0 外接 LED）：`HAL_Init()` + `__HAL_RCC_GPIOA_CLK_ENABLE()` + PA0 推挽输出 + `TogglePin` 500ms 循环
- 用户手写版检查出两个 bug：① 变量名不一致（声明 `GPIO_InitStruct`、使用 `gpio` → undeclared）；② include 应为 `stm32f1xx_hal.h`（`stm32f1xx.h` 只是寄存器头，无 HAL API）
- `SysTick_Handler` 已在 `stm32f1xx_it.c:183` 存在（`HAL_IncTick`），无需重复定义

### 硬件：面包板接线 + 供电原理 + LED 不亮排查
- 江科大 STM32 入门视频：学会面包板基本用法（正负极轨、**中心凹槽两侧不导通**）
- 供电接法：ST-Link 3.3V → 面包板正极轨，GND → 负极轨；LED 正极（长脚）经 330Ω 电阻 → 3.3V，**负极（短脚）→ PA0**
- 为什么这么接：① 共地是 SWD 烧录信号的前提；② 电流回路必须闭合；③ 负极接 PA0 = 低电平点亮（sink 接法），复位后浮空输入灯不误亮
- **灯不亮排查链**：先验证烧录（`Download verified successfully`，固件确实在 Flash）→ 代码逻辑复查（Toggle 极性正确）→ 电路检查（极性/电阻/凹槽/PA0 丝印）→ **根因：LED 灯珠本身坏了**，换新灯珠后 0.5s 正常闪烁 ✅

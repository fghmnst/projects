### `.settings` 跨平台复制坑（wsl 无法生成 → win 复制 → 又报错）
- **前置**：昨晚 `cube bundle init --project` + 手补 `ide.store.json` 后，重启电脑扩展自动下载配置成功（`.settings/` 三件套齐）
- **坑 1：禁止跨平台复制 `.settings/`**——Windows 端生成的 `bundles.store.json`/`bundles-lock.store.json` 带 **`platform: darwin`** 标记，WSL（linux）端 `cube bundle list --project`「当前平台」只剩 cmake 匹配，工具链解析异常 → **删除重建**：`rm bundles*.json` + `cube bundle init --project --yes`（WSL 端重新生成）
- **坑 2：复制瞬间空文件** → `bound doStepSettingsValidation Failed: Device not found: SyntaxError: Unexpected end of JSON input`——`JSON.parse("")` 异常（Unexpected end of JSON input）被 project-manager 透传成 device 名（`getDeviceAndBoard` 收到异常消息字符串）；复制完成文件完整后错误自愈
- 结论：`.settings/` 是**平台相关的 runtime 状态，各平台各自生成**，已加入根 `.gitignore`

### LED 点灯：PA6 → PA1（失败）→ 脉冲定位 → PC13（成功）⭐
- 最初计划：PA6 外接灯（Lesson 1 补了 PA6 接线笔记 + 位置说明）
- 改 PA1 板载（`main.h` 宏切换）→ 烧录后**灯不闪**——C8T6 蓝板 **PA1 并没有板载 LED**（电源灯旁那个出厂闪烁的灯不是 PA1！）
- **脉冲定位法**（确定未知 LED 引脚的标准流程）：
  1. 扫引脚程序：15 个候选引脚（PA0-7、PB0/1/10/11、PC13-15）轮流「高 0.5s + 低 0.5s」→ 用户观察灯约 14s 亮起 → 缩小到 PC14/PC15
  2. 脉冲计数模式：每引脚「亮 0.5s + DeInit 高阻 1.5s 间隔」→ 数第几个脉冲 → 用户推断 PC13
- **PC13 烧录成功：0.5s 亮灭交替**（Blue Pill 传统引脚，低电平点亮；需 `__HAL_RCC_GPIOC_CLK_ENABLE()`——生成代码区外手改，与 `.ioc` 未同步，见待办）
- 教训：**廉价 C8T6 蓝板 LED 引脚厂牌不一，别猜，用脉冲定位法一次锁定**

# Linux 重定向：文件描述符与 2>&1 详解

> [!note] 缘起
> 处理 Obsidian 日志刷屏时反复出现 `2>&1`，它是 shell 语法里最常用也最容易误解的一条。本文把"文件描述符"讲透，再拆解 `2>&1` 的每一个字符，包括它最常见的坑：**书写顺序**。

相关：[[Linux入门-chmod权限与JobControl任务控制]]

---

## 一、先理解：程序的三个"默认出口"

每个 Linux 程序启动时，shell 都会给它三个已打开的数字通道，叫**文件描述符（file descriptor）**：

| 编号 | 名称 | 默认指向 | 用途 | 记忆 |
| --- | --- | --- | --- | --- |
| 0 | stdin（标准输入） | 键盘 | 程序读入 | 键盘 0 根手指？可作首 |
| 1 | stdout（标准输出） | 屏幕 | 正常结果 | "1"像一根竖线，正常输出 |
| 2 | stderr（标准错误） | 屏幕 | 错误/日志信息 | 出问题的是"2" |

> [!note] 为什么默认有两个出口都指向屏幕？
> 正常结果（1）和错误信息（2）分开编号，是为了让你能把它们**分别**导入不同文件——比如只要错误、不要正常输出。

确认一个命令的三通道指向哪：

```bash
echo hello > /dev/null          # hello 进黑洞（标准输出被重定向）
ls /nonexistent 2> /dev/null    # 错误信息被吞掉
```

## 二、重定向的"指向"语法

| 写法 | 含义 | 类比 |
| --- | --- | --- |
| `> 文件` | 把 **1**（stdout）写入文件（覆盖） | 打印稿换新页 |
| `>> 文件` | 把 **1** 追加到文件末尾 | 打印稿续页 |
| `< 文件` | 把 **0** 改为从文件读取 | 喂进去 |
| `2> 文件` | 把 **2**（stderr）写入文件 | 错误单独归档 |
| `2>> 文件` | 把 **2** 追加到文件 | — |
| `&>` | 同时重定向 1 和 2（bash 简写） | 一锅端 |

注意：`>` 前面**不写数字时默认是 1**，所以 `> 文件` 等价于 `1> 文件`。

---

## 三、`2>&1` 逐字符拆解

```bash
命令 2>&1
```

| 字符 | 含义 |
| --- | --- |
| `2` | 第二个文件描述符：**stderr（标准错误）** |
| `>` | 重定向符号："把前面的东西指到后面去" |
| `&1` | 指向文件描述符 **1**（& = 引用另一个描述符，不是文件名！） |

### 为什么 `&1` 而不是 `1`？

因为**必须区分"文件叫 1"和"描述符编号 1"**。`&` 表示"后面是描述符"。如果写 `2>1`，shell 会认为你想把 stderr 写进**一个名叫 `1` 的文件**——这是初学者最容易踩的坑：

```bash
命令 2>1      # 错误：创建了一个名为 "1" 的文件！
命令 2>&1     # 正确：stderr 合并到 stdout
```

### 本质语义

`2>&1` = "把 stderr **复制**到 stdout 当前指向的位置"。它是**复制指向（dup）**，不是简单的"输出合并"——所以顺序非常关键（见下节）。

---

## 四、最常见的坑：书写顺序

```bash
命令 > log.txt 2>&1     # ✓ 正确：1 指 log.txt，2 再指向"1 现在的位置"= log.txt
命令 2>&1 > log.txt     # ✗ 错误：2 先指向"1 现在的位置"= 屏幕，1 之后才改指 log.txt
```

逐行推演正确版本（从左到右执行）：

| 执行到 | 1 (stdout) 指向 | 2 (stderr) 指向 |
| --- | --- | --- |
| 初始 | 屏幕 | 屏幕 |
| `> log.txt` | **log.txt** | 屏幕 |
| `2>&1` | log.txt | **log.txt**（复制 1 的当前指向） |

再推演错误版本：

| 执行到 | 1 指向 | 2 指向 |
| --- | --- | --- |
| 初始 | 屏幕 | 屏幕 |
| `2>&1` | 屏幕 | 屏幕（复制 1 此刻的指向：还是屏幕！） |
| `> log.txt` | log.txt | **屏幕**（为时已晚） |

> [!warning] 记忆口诀
> **"先开新去向，再复制指向"**——`> 文件 2>&1` 才对；顺序反了，错误信息照样漏到屏幕上，log.txt 里只有正常输出。

## 五、实战组合

```bash
obsidian-gui > ~/obs.log 2>&1 &     # 正常+错误都进日志，后台跑
obsidian-gui &> /dev/null &          # bash 简写：全部丢弃，后台跑
make > build.log 2>&1                # 编译日志完整留存
script.sh 2>&1 | tee result.log      # 合并后再管道给 tee（tee 同时输出到屏和文件）
```

`&>` 等价于 `> 文件 2>&1`，但只在 bash 里可用（sh 不认），且它**不关心顺序**——简写虽然省事，理解其展开式仍是基本功。

---

## 六、小结

1. 0/1/2 = 输入 / 正常输出 / 错误输出，默认全在终端
2. `2>&1` = "把 stderr 复制到 stdout 当前指向的位置"，`&` 表示"引用描述符而非文件名"
3. **先 `> 文件` 后 `2>&1`**，顺序不可颠倒
4. `2>1` 会创建一个叫 1 的文件——永远记得写 `&`

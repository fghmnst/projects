# RAG 与 MCP：概念及本仓库适用性判断

> [!note] 缘起
> 一次「要不要给学习工作流引入 AI 基础设施」的讨论。结论：概念值得了解，但本仓库当前规模**不需要**引入，理由与触发条件记录如下，供以后复查。

## 一、RAG 是什么

**RAG（Retrieval-Augmented Generation，检索增强生成）**：让 LLM 回答「它没学过 / 不该硬记」的资料时，**先检索证据、再生成回答**的一套做法。

要解决的矛盾：

- 模型知识冻结在训练时，无法知道你的私有文档与最新信息；
- 上下文窗口有限，装不下全部资料。

典型流程：

```
文档 → 切块（chunk）→ 向量化（embedding）→ 存入向量库
提问 → 问题向量化 → 相似度检索 top-k 片段 → 拼进提示词 → 模型据片段作答
```

| 优点 | 局限 |
|---|---|
| 答案可溯源（有出处） | 切块与召回质量决定效果，工程调优是大头 |
| 知识可随时更新，不用重训模型 | 对需要全局理解的内容，取片段会丢上下文 |
| 私有资料不必进训练集 | 引入向量库等额外基础设施与维护成本 |

## 二、MCP 是什么

**MCP（Model Context Protocol，模型上下文协议）**：AI 应用（client）与外部工具/数据（server）之间的**标准接口协议**。

- 类比：AI 界的 USB-C，或编程界的 LSP（语言服务器协议）——server 一次实现，多个 AI 客户端都能接。
- 两种形态：
  - **local**：本地子进程，通过 stdio 通信（如 `npx` 启动的 server）；
  - **remote**：HTTP 服务，可带 OAuth 或 API Key（headers）。
- 在 opencode 中：配置文件 `mcp` 字段声明，工具自动并入内置工具；管理命令 `opencode mcp list` / `opencode mcp auth <name>`。
- 官方提醒：MCP 工具**会占上下文**，装多了容易爆 token，宜少而精。
- 常见 server：Context7（查框架文档）、GitHub、Sentry、浏览器自动化、数据库等。

## 三、两者关系

| | RAG | MCP |
|---|---|---|
| 管什么 | **知识怎么进模型**（检索后拼进提示词） | **工具怎么接进模型**（标准接口调用外部能力） |
| 层次 | 应用策略 | 通信协议 |
| 关系 | 正交、不互斥；一个 MCP server 内部可以自己实现 RAG | |

## 四、本仓库适用性判断（2026-09 结论：暂不需要）

| 理由 | 说明 |
|---|---|
| 语料太小 | 知识库是本仓库内的 markdown（几十篇、单篇 KB 级）；agent 用直接文件读取 + `grep`/`glob` + 索引页就是精确检索，比向量检索更准且零基础设施 |
| 工作模式不匹配 | opencode 直接读写文件、Hermes 在服务器 clone 上直接读日志——「仓库即上下文」。RAG 的切块会丢掉跨段落语境，对日志/计划/复盘类内容反而有害 |
| 没有要接的外部服务 | 外部能力已由 shell + git + obsidian CLI + ssh 只读 + skills 覆盖；MCP 凭据不能进公开仓库（只能放 env），多一层维护与安全面 |
| 收益条件未到 | RAG 的价值在「语料大到无法直接读」；MCP 的价值在「接一个没有 CLI、会反复用的服务」，两者都还没出现 |

> [!tip] 顺带澄清
> Hermes 晨报**不是 RAG**：它的「检索」是 `git pull` + 按固定路径读昨日日志，属于确定性流水线；对这种固定任务，确定性流程比 RAG 更可靠。详见 [[somezhishi/环境排障/Hermes-云部署指南-飞书每日推送|Hermes 云部署指南]]。

## 五、什么时候重新评估

| 触发条件 | 考虑引入 |
|---|---|
| 语料涨到几百上千篇笔记 / 大量 PDF / 教材，且 `grep` 式检索开始不够用 | RAG（可先做轻量方案：更好的索引页、标签、Bases 视图，再考虑向量检索） |
| 云端 Hermes 需要回答「整个知识库」的语义问题 | RAG |
| 要接入一个没有 CLI、没有现成 skill、但会反复使用的第三方服务（深度 GitHub 操作、浏览器自动化等） | MCP（opencode 已原生支持，随时可加） |
| 多个 AI 客户端想共享同一套工具实现 | MCP |

## 六、术语速查

| 术语 | 含义 |
|---|---|
| embedding（向量化） | 把文本映射成高维向量，语义相近的文本向量距离近 |
| chunk（切块） | 把长文档切成适合检索的小段 |
| top-k | 检索返回相似度最高的 k 个片段 |
| rerank（重排序） | 对初检结果用更精细的模型重新排序，提高相关性 |
| BM25 | 经典关键词检索算法（非向量路线） |
| client / server | MCP 中请求方（AI 应用）/ 能力提供方（工具服务） |
| stdio | 本地 MCP 常用的进程间通信方式（标准输入输出） |

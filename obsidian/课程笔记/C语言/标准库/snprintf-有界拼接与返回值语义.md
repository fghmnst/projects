# snprintf：有界拼接与返回值语义（新手版）

> [!note] 一句话先行
> `snprintf` 是 printf 家族里"往你自己的字符串缓冲区写、且带保险丝"的那个：最多写 `size-1` 个字符，然后补 `'\0'`。返回的 `int` 有两种含义——非负表示"**假如地方管够，本应写多少字符**"（用它可以判断截断），负数表示失败。

## 一、先定位：printf 家族对照

| 函数 | 写到哪 | 有容量限制吗 |
| --- | --- | --- |
| `printf` | 屏幕（stdout） | 不适用 |
| `fprintf` | 任意 `FILE *` 通道 | 不适用 |
| `sprintf` | **你的字符串缓冲区** | ❌ 没有，写超直接踩坏内存 |
| `snprintf` | **你的字符串缓冲区** | ✅ 有，最多写你允许的字节数 |

`snprintf` = "**s**tring + **n**（限 n 字节）+ print f"；它家所有函数都住在 `<stdio.h>`（是 printf 一族，不是 string 一族）。

## 二、传入什么（原型逐参数）

```c
int snprintf(char *str, size_t size, const char *format, ...);
```

1. `str`：**你提供的**字符数组（目的地）。函数只往里写，不帮你分配内存；
2. `size`：这块地方的总容量（字节数）。函数保证最多写 `size - 1` 个字符，然后补 `'\0'`——**这条"保险丝"就是它和 `sprintf` 的全部区别**；
3. `format` + `...`：与 `printf` 完全相同的格式串和参数（`%s` 接字符串、`%d` 接整数、`%zu` 接 `size_t`……）。

## 三、传出什么：两个"出口"

**出口一：缓冲区里被写进的内容。** 括写字符 + 自动补的 `'\0'`。地方不够就**截断**——只写放得下的部分，但**永远保证 `'\0'` 结尾**（只要 `size > 0`）。最坏情况是"内容不全"，绝不会是"字符串没有结尾"那种更可怕的崩溃。

**出口二：返回一个 `int`，含义分两种**：

- **非负**：表示"**假如地方管够，本应写多少个字符**"——注意不是"实际写了多少"，且不含结尾 `'\0'`；
- **负数**：编码错误 / 失败，常见是 -1。

"本应写多少"的语义是全场最妙的设计，看例子：

```c
char buf[8];
int n = snprintf(buf, 8, "%s", "hello world");
// buf 里是 "hello w"（7 个字符 + '\0'）
// n = 11 —— 即使实际只放下了 7 个
```

所以 `n >= size` 就等于"**被截断了，内容不完整，别用**"。

**两段式技巧**：先 `snprintf(NULL, 0, fmt, ...)` 探出所需长度（size 传 0 时允许 `str` 为 `NULL`，什么都不写、只报长度），再 `malloc` 出足够空间正式写。

## 四、note-stats.c:36-38 逐参数对照

```c
char child[1024];                                                        /* :36  栈上缓冲 */
int n = snprintf(child, sizeof child, "%s%s", dirpath, entry->d_name);   /* :37  拼接 */
if (n < 0 || (size_t)n >= sizeof child) { ... 跳过 ... }                 /* :38  校验 */
```

- `child`：目的地，1024 字节；
- `sizeof child`：数组还是"数组身份"时，`sizeof` 给出总字节数 1024，正好当容量（这就是 `size_t` 与 `sizeof` 的实战）；
- `"%s%s"`：首尾相接拼出路径；
- 校验链路：`n < 0` 先挡失败；`||` 短路保证只有非负时才强转 `(size_t)n`；`n >= 1024` 即"本该更长、被截断"，半截路径不可用。详解见 [[课程笔记/C语言/语言基础/size_t-无符号长度类型与有符号陷阱|size_t 笔记]]第五节。

> 一个值得注意的**隐藏契约**：`"%s%s"` 中间没插 `/`，所以调用时目录参数要自带结尾斜杠（如 `./note-stats obsidian/`）；否则会拼出 `obsidian每日日志` 这类粘连路径，`stat` 全部找不到。初稿在这里踩过坑、修正为 `"%s/%s"` 的经过见 [[课程笔记/C语言/项目实战/目录遍历与递归-note-stats步骤2|目录遍历与递归步骤 2]]。

## 五、什么时候会用到它

| 场景 | 说明 |
| --- | --- |
| 拼字符串 | 路径、文件名、日志消息（本程序） |
| 数字 → 字符串 | C 没有自动装箱，`snprintf(buf, sizeof buf, "%d", x)` 是标准转法 |
| 组协议帧 | 把字段格式化成一行文本塞进发送缓冲（串口通信 / 调试输出常用） |
| 探长度再分配 | `snprintf(NULL, 0, ...)` 两段式 |
| 替代 sprintf | 现代 C 代码默认用 `snprintf`，纪律同"默认用安全函数" |

> 进阶坑：格式串里的 `%s` 若源与目的缓冲区是同一块（自拼自己），行为未定义——需要就先拷到临时区。

## 术语小词典

| 词 | 大白话 |
| --- | --- |
| 缓冲区（buffer） | 一块预备放字符的内存，如 `char child[1024]` |
| 截断（truncation） | 地方不够，内容被切掉一截 |
| NUL 结尾 | C 字符串靠一个值为 0 的字节标记结束 |
| 变参函数（variadic） | 参数个数不固定、靠格式串指路的函数 |
| 两段式用法 | 先探长度、再分配、最后正式写 |

## 自测

> [!question]- 想好再展开
> 1. `n` 返回 11 但缓冲区只有 8 字节——`n` 数的是"实际写的"还是"本该写的"？note-stats.c:38 如何利用它？
>    答：数的是"本该写的"（不含 `'\0'`）。`n >= sizeof child` 说明截断，半截路径不可用，`continue` 跳过。
> 2. 为什么校验里先写 `n < 0 ||` 再强转，而不是直接 `(size_t)n >= sizeof child`？
>    答：短路让失败时不做强转；同时在符号信息丢失前判负，避免依赖"负数回绕成巨大值"的巧合。
> 3. `snprintf` 的 `size` 参数能防什么？写不下时字符串会没有结尾吗？
>    答：防越界写（保险丝）；只要 `size > 0` 就总会补 `'\0'`，不会出现无结尾字符串。

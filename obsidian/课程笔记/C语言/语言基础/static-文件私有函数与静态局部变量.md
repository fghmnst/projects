# static：文件私有函数与静态局部变量（新手版）

> [!note] 一句话先行
> `static` 在 C 里"一词两义"：贴在**函数 / 全局变量**前 = 只在本文件内可见（部门内部工牌）；贴在**函数内部的局部变量**前 = 活到程序结束、跨调用记住值。note-stats 的两处 `static` 都是第一义：文件内的辅助函数默认私有，是 C 程序的好习惯。

## 一、一词两义，先分清

| 贴在哪 | 管什么 | 一句话 |
| --- | --- | --- |
| 函数 / 全局变量前 | 可见范围（链接性） | 只在本文件内可见 |
| 函数内部的局部变量前 | 寿命（存储期） | 活到程序结束，跨调用记住值 |

同一个关键字管两件不相干的事，是 C 的历史包袱；读代码时先看它贴在哪。

## 二、函数前的 static：部门内部工牌

note-stats.c:8 与 :19 的 `static` 就是这个意思：`has_md_suffix`、`scan_dir` 是**本文件的私有员工**，别的 `.c` 文件不许点名调用。

比喻：不加 `static` 的函数，名字被写进"公司总通讯录"（全局符号表），全公司（所有编译单元）可见、可能重名；加了 `static` 就只是一张部门工牌，出了这个文件没人认识。

## 三、去掉 static 的三笔账

在**当前单文件程序**里，去掉 `static` 照样编译运行（没有第二个文件来撞名）。但有三笔账：

1. **撞名雷**：以后拆分多文件（比如另写一个 `util.c` 也定义 `scan_dir`），链接器会看到两个同名全局符号，直接报错：

   ```
   multiple definition of 'scan_dir'; first defined here
   ```

2. **丢掉"私有"信息**：编译器不知道"外部没人会调它"，更保守，内联等优化受限；开了 `-Wmissing-prototypes` 还会对没原型的全局函数发警告；
3. **接口污染**：没必要的符号暴露出去，别人可能误依赖；将来想改函数签名都投鼠忌器。

社区惯例很简单：**文件内的辅助函数默认一律 `static`，只有明确对外提供的才去掉。**

## 四、另一义：函数内部的 static 局部变量

```c
void greet(void)
{
    static int count = 0;   // 只在程序启动时初始化一次
    count++;
    printf("第 %d 次打招呼\n", count);
}
```

- 普通局部变量住"栈"上，函数一返回就销毁；`static` 局部变量住全局数据区，**返回后依然活着**，下次调用还记得上次的值，且只初始化一次；
- 因为所有调用共享同一份，它**不是线程安全的**，可重入性也差。要用先想清楚：是不是真的需要"跨调用记忆"（懒初始化 / 计数器 / 缓存），否则优先把状态通过参数传。

## 五、使用清单

| 场景 | 用法 |
| --- | --- |
| 文件内部的辅助函数、查找表、常量 | `static`（函数 / 全局变量） |
| 跨调用保留状态的局部变量 | 函数内 `static` 局部变量，留意线程安全 |
| 对外提供的接口 | **不** `static`（配头文件声明） |
| 头文件里定义的小函数 | `static inline`：每个包含者各有一份拷贝，避免重复定义 |

## 术语小词典

| 词 | 大白话 |
| --- | --- |
| 链接性（linkage） | "这个名字允许被哪些文件看见"的规则 |
| 内部链接 | `static`：只在本文件内可见 |
| 外部链接 | 默认：全程序可见，链接器按名字对接 |
| 存储期（storage duration） | 变量活多久：栈变量活到函数返回，静态变量活到程序结束 |
| 可重入 / 线程安全 | 多个执行流同时进来会不会互相踩 |

## 自测

> [!question]- 想好再展开
> 1. `static int scan_dir(...)` 和函数内 `static int count = 0;` 里的 `static`，解决的是同一个问题吗？
>    答：不是。前者管"可见范围"（只在本文件可见），后者管"寿命"（活到程序结束、跨调用保值）。
> 2. 单文件程序里"去掉 static 也能跑"，为什么还说是好习惯？
>    答：它提前避免了将来拆分多文件时的同名冲突，向编译器和读者标明"这是私有实现"，并减少对外符号污染。

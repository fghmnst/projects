# size_t：无符号长度类型与有符号陷阱（新手版）

> [!note] 一句话先行
> `size_t` 是"量长度的尺子"：**无符号**、**宽度随平台自动加长**（保证装得下任何对象大小）、**语义就是"多少"**。凡是和标准库的"长度接口"打交道（`strlen` / `sizeof` / `snprintf` / `malloc`），默认用它；一旦进入无符号比较，**先判负、再转换**——负数转 `size_t` 会变成天文数字。

## 一、它在哪：户籍 `<stddef.h>`，但到处都有

标准答案：`size_t` 定义在 **`<stddef.h>`**（standard definitions，专门放基础类型）。但 C 标准特意规定 `stdio.h`、`string.h`、`stdlib.h` 等一批常用头文件**也必须顺带定义它**——note-stats 没 include `stddef.h` 却能用 `size_t`，就是因为 `stdio.h` / `string.h` 已经把它带了进来。

## 二、三个特点与它存在的理由

1. **无符号**：量长度不该为负；
2. **宽度随平台**：32 位平台 4 字节、64 位平台 8 字节——保证"装得下本平台任何对象的大小"。这才是它存在的核心：`int` 宽度固定，理论上可能不够；
3. **语义即"长度 / 容量"**：接口自解释。

典型接口（返回值或参数类型就是 `size_t`）：

| 接口 | 哪里用到 |
| --- | --- |
| `sizeof x` | 编译期结果类型就是 `size_t` |
| `strlen(s)` | 返回 `size_t` |
| `snprintf(buf, size, ...)` | 第二个参数（容量）是 `size_t` |
| `malloc(n)` / `calloc(n, m)` | 参数是 `size_t` |
| `fread(ptr, size, n, f)` | 第 2、3 参 |
| `memcpy` / `memset` 第三参 | 字节数 |

note-stats 对应两处：`size_t len = strlen(name);`（note-stats.c:10）与 `(size_t)n >= sizeof child`（note-stats.c:38）。

## 三、什么时候该用 / 不该用

**该用**：① 接标准库长度接口；② 自己写"类库"函数（模仿标准库风格，如 `void copy_n(char *dst, const char *src, size_t n)`）；③ 下标要和长度比较时。

**不该用**：

| 场景 | 应改用 | 原因 |
| --- | --- | --- |
| 要表示"失败"（如 `snprintf` 出错返回 -1） | `int` | 无符号装不下负数 |
| 系统调用返回"字节数或 -1"（`read` / `recv`） | `ssize_t` | 有符号版的 `size_t` |
| 指针差值、可能为负的偏移 | `ptrdiff_t` | 有符号；定义也在 `<stddef.h>` |

**倒序循环的经典坑**：

```c
size_t i = n - 1;
while (i >= 0) { ... i--; }        // 死循环：无符号永远 >= 0

for (size_t i = n; i-- > 0; ) { ... }   // 安全写法之一
```

## 四、用 int 代替的三档后果

假设写 `int len = strlen(name);` 或 `int n = snprintf(...)`：

1. **转换警告**：8 字节无符号塞进 4 字节有符号，编译器碎碎念（开 `-Wconversion` 时更响）；
2. **混比惊魂**：`n` 与 `size_t` 比较时，`n` 被隐式转成无符号。`n = -1` 直接变成 `18446744073709551615`（2⁶⁴-1）——"很小"瞬间变"极大"；
3. **溢出未定义**：长度真超过 `INT_MAX` 时，有符号溢出在 C 里是**未定义行为**——编译器怎么优化都合法。

## 五、实战：note-stats.c:37-38 的写法为什么对

```c
int n = snprintf(child, sizeof child, "%s%s", dirpath, entry->d_name);
if (n < 0 || (size_t)n >= sizeof child)
```

- `n` 用 `int` 收：要兼容"负数 = 失败"这个约定（见 [[课程笔记/C语言/标准库/snprintf-有界拼接与返回值语义|snprintf 笔记]]）；
- `n < 0` 先判：`||` **短路求值**，失败时后面的强转根本不执行；
- `(size_t)n >= sizeof child`：只有非负时才转换，此刻转换是保值的；再和容量比较，判断"本该写更长 = 被截断"。

**反事实实验**：若交换顺序写成 `(size_t)n >= sizeof child || n < 0`，`n = -1` 时第一个比较也会因天文数字而成立——**在这段代码里碰巧仍走对分支**。但这是巧合兜底，不是设计：将来想区分两种失败、拿 `n` 做减法、或改比较方向，就会当场翻车。纪律一句话：**在符号信息丢失之前（强转之前）先把"可能为负"拦住。**

## 术语小词典

| 词 | 大白话 |
| --- | --- |
| `size_t` | 无符号长度类型，宽度随平台自动适配 |
| `ssize_t` | 有符号版，专门给"字节数或 -1"的系统调用 |
| `ptrdiff_t` | 指针相减的结果类型，有符号 |
| 隐式转换 | 类型不匹配时编译器悄悄替你转，方向不对就出坑 |
| 回绕（wrap） | 负数转无符号后按模 2ⁿ 变成巨大正数 |
| `%zu` | printf 家族打印 `size_t` 的格式符 |
| 未定义行为（UB） | 标准说"这样写我不管了"，结果不可预测 |

## 自测

> [!question]- 想好再展开
> 1. `size_t` 的"标准户籍"是 `<stddef.h>`，为什么 note-stats 没 include 它也能编译？
>    答：`stdio.h` / `string.h` 等常用头文件按 C 标准必须顺带定义 `size_t`，已经带进来了。
> 2. `(size_t)(-1)` 等于多少？这算未定义行为吗？
>    答：18446744073709551615（2⁶⁴-1）。不算 UB——有符号转无符号按模 2ⁿ 回绕，结果有标准保证，但极具迷惑性。
> 3. 为什么 `n < 0 || (size_t)n >= sizeof child` 要把 `n < 0` 放前面？
>    答：① 短路让失败时不做强转；② 在符号信息丢失前判断，不依赖回绕的巧合。

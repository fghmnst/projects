# S_ISDIR 与 S_ISREG：位掩码宏与 mode_t（新手版）

> [!note] 一句话先行
> `S_ISDIR` / `S_ISREG` 不是函数，是**宏**：展开后"用掩码抠出类型位、再与编码比对"，传入 `st_mode`（结构体里唯一装类型信息的成员），返回 `int` 的 0 或 1。note-stats.c:55 用它和 `has_md_suffix` 组成**双闸门**：类型对 + 名字对，才打印。

## 一、先纠偏：它不是函数，是宏

它长着函数的脸，其实是一段**文本替换规则**（function-like macro），住在 `<sys/stat.h>`。本机真身（`sys/stat.h:123-128`）：

```c
#define __S_ISTYPE(mode, mask)  (((mode) & __S_IFMT) == (mask))
#define S_ISDIR(mode)  __S_ISTYPE((mode), __S_IFDIR)
#define S_ISREG(mode)  __S_ISTYPE((mode), __S_IFREG)
```

预处理器看到 `S_ISDIR(st.st_mode)`，就在编译前**原地展开**成：

```c
(((st.st_mode) & 0170000) == 0040000)
```

没有函数调用、不入栈、也不做类型检查——只是"把参数塞进公式里算一遍表达式"。常量来自 `bits/stat.h:29-38`：`0170000` 是类型掩码 `__S_IFMT`，`0040000`（目录）/ `0100000`（普通文件）是编码。

宏的通用纪律：定义时参数带括号、调用时别塞出副作用的表达式（宏按文本替换，优先级和求值次数都可能给你惊喜）。

## 二、传入什么、返回什么

- **传入**：一个"模式值"（`mode_t` 类型的整数）——参数名就叫 `mode`，不是巧合；
- **返回**：比较表达式产生的 `int`——**1 = "是"，0 = "不是"**，直接当 `if` 条件用。

## 三、八进制演算两例

把 `st_mode` 想成"二进制拼盘"：**高位段写类型，低位段写权限**。掩码 `0170000` 的作用是"只尝类型那段、遮住权限那段"：

```c
/* 例1：目录，ls 显示 drwxr-xr-x，st_mode = 0040755 */
0040755 & 0170000 = 0040000        /* 遮掉权限位，只剩类型位 */
0040000 == 0040000 → 1            /* 是目录 ✅ */

/* 例2：普通文件 -rw-r--r--，st_mode = 0100644 */
0100644 & 0170000 = 0100000
0100000 == 0040000 → 0            /* 不是目录 ❌ */
```

注意：**要传完整的 `st_mode`，不是自己抠好的类型值**——掩码这步由宏内部完成。这也解释了为什么不能写 `st_mode == 0040000`：权限位没被遮，目录带任何权限都比不中。

## 四、为什么传 `st_mode`，而不是别的成员

因为整个 `struct stat` 里**只有 `st_mode` 装着"类型"信息**。逐个排除：

| 成员 | 装的是 | 为什么不能判类型 |
| --- | --- | --- |
| `st_size` | 文件字节数 | 目录也有大小，尺寸与"是不是目录"无关 |
| `st_ino` | inode 编号 | 只是身份证号，不区分职业 |
| `st_nlink` | 硬连接数 | 目录通常 ≥2，但普通文件也能有硬连接——不能当判据 |
| `st_uid` / `st_gid` | 属主 | 与"是什么"正交 |
| `st_atim` / `st_mtim` | 时间戳 | 与类型正交 |
| `st_dev` | 所在设备 | 在哪文件系统，不是类型 |

## 五、`st_mode` 是什么类型：为什么能做位运算

顺着本机头文件把类型链追到底：

```c
/* bits/struct_stat.h:41/45 */
__mode_t st_mode;                    /* ① 成员类型 __mode_t */
/* bits/types.h:150 */
__STD_TYPE __MODE_T_TYPE __mode_t;   /* ② __mode_t = __MODE_T_TYPE */
/* bits/typesizes.h:43 */
#define __MODE_T_TYPE  __U32_TYPE    /* ③ = 32 位无符号整数 */
```

在 x86_64 Linux 上，`__mode_t` 最终就是 **`unsigned int`**（POSIX 正式名 `mode_t`，`sys/types.h:69` 的 `typedef __mode_t mode_t;`）。types.h:150 的注释写得很直白：**"Type of file attribute bitmasks"（文件属性位掩码的类型）**——它从出生就是为位运算设计的。

**能运算的根本原因**：C 里整数就是"可以逐位摆弄的二进制串"，`&` 这类位运算符就是为整数类型准备的。设计者故意把两样东西打包进同一个整数：

```
st_mode（32 位，实际用到低 16 位）:
 位 15 ─ 12 : 类型段（S_IFMT 0170000 抠这段）
 位 11 ─  0 : 权限段（07777 = rwxrwxrwx + setuid/setgid/sticky）
```

## 六、算出来的结果意味着什么：0 / 1 与双闸门

`S_ISREG(st.st_mode)` 展开是 `((st.st_mode & 0170000) == 0100000)`：`==` 产生 `int`，**1 = 是普通文件，0 = 不是**（目录、符号链接、设备、FIFO、socket 全算"不是"）。

接在 note-stats.c:55 里组成双闸门：

```c
else if(S_ISREG(st.st_mode) && has_md_suffix(entry->d_name))
```

- **类型门**：`S_ISREG`——系统权威回答"它确实是普通文件吗"；
- **名字门**：`has_md_suffix`——名字以 `.md` 结尾吗（名字层判断）；
- `&&` 短路：类型门不过，连名字都不查。

为什么缺一不可（名字与类型是正交的）：

- 一个**名叫 `笔记.md` 的目录**：名字门过、类型门不过——不会打印（它在更上面的 `S_ISDIR` 分支已被递归进去）；
- 指向 `.md` 文件的**符号链接**：`stat` 跟随链接、报告目标类型 = 普通文件，两道门都过，会打印（`stat` / `lstat` 的选择细节）；
- 命名为 `x.md` 的 **FIFO**：类型门拦下。

> 别把 `d_type` 混进来：`readdir` 的 `DT_*` 是**另一套编码**（`DT_DIR=4` 这类小数字），`S_ISDIR` 不认它；换算宏是 `IFTODT`。同一信息、两套表示。

## 术语小词典

| 词 | 大白话 |
| --- | --- |
| 函数式宏 | 长得像函数调用、实为文本替换的宏 |
| 展开（expansion） | 预处理阶段把宏原地替换成定义体 |
| 位掩码（bitmask） | 用 `&` 抠出整数中某几位的过滤网 |
| 位字段打包 | 把一个整数分段使用，每段装不同信息 |
| `mode_t` / `__mode_t` | mode 值的类型；本机为 `unsigned int` |
| 正交检查 | 两个条件互不蕴含，各自拦一类错误 |

## 自测

> [!question]- 想好再点开
> 1. `S_ISREG(st.st_mode)` 展开后的完整表达式是什么？为什么结果只能是 0 或 1？
>    答：`((st.st_mode & 0170000) == 0100000)`；`==` 运算符的结果在 C 里恒为 `int` 的 0 或 1。
> 2. 名叫 `foo.md` 的目录走进 note-stats.c:51-58：它会在哪一支被处理？为什么最后不会打印？
>    答：`S_ISDIR` 先命中，走递归分支；即使名字门过，它也不会进打印分支——类型门只对普通文件放行。
> 3. 为什么 `st_mode == 0040000` 不能用来判目录？
>    答：`st_mode` 同时含权限位；直接比较等于"类型 + 权限整体相等"，权限一变就判错，必须先 `& 0170000` 遮掉权限段。

# struct stat：文件体检报告与 stat 家族（新手版）

> [!note] 一句话先行
> `struct stat` 是文件的**元数据"体检报告"**：类型、大小、属主、时间一应俱全，唯独没有内容。`stat(path, &st)` 负责填表——成功返回 0，失败 -1 并写 `errno`；**失败时 `st` 内容未指定**，所以必须"先判返回值，再读结构体"。
> 相关：[[课程笔记/C语言/C语言|C语言]] · [[课程笔记/C语言/系统接口/S_ISDIR与S_ISREG-位掩码宏与mode_t|S_ISDIR 与 S_ISREG]] · [[课程笔记/C语言/系统接口/opendir与DIR句柄-从POSIX讲起|opendir 与 DIR 句柄]] · [[课程笔记/C语言/项目实战/目录遍历与递归-note-stats步骤2|目录遍历与递归]]

## 一、声明在哪：同样的"套娃"链

`struct stat` 属于 POSIX 家族，入口是 `<sys/stat.h>`；glibc 里的层级：

```c
/* /usr/include/x86_64-linux-gnu/sys/stat.h */
#include <bits/stat.h>          /* 类型掩码、S_ISDIR 等宏 */
        /* ↓ */
#include <bits/struct_stat.h>   /* struct stat 本体（:26-99） */
```

本机真实字段（简化版）：

```c
struct stat
{
    __dev_t   st_dev;       /* 文件在哪个设备（文件系统）上 */
    __ino_t   st_ino;       /* inode 号——和 dirent 的 d_ino 同一个东西 */
    __nlink_t st_nlink;     /* 硬连接数 */
    __mode_t  st_mode;      /* 类型 + 权限，打包成一个整数 ← 主角 */
    __uid_t   st_uid;       /* 属主用户 */
    __gid_t   st_gid;       /* 属主组 */
    __off_t   st_size;      /* 文件大小（字节） */
    __blksize_t st_blksize; /* 建议的 I/O 块大小 */
    __blkcnt_t  st_blocks;  /* 实际占用的 512 字节块数 */
    struct timespec st_atim;/* 最后访问时间 */
    struct timespec st_mtim;/* 最后修改时间 */
    struct timespec st_ctim;/* 最后状态变更时间 */
    ...若干填充 / 保留字段...
};
```

字段顺序与填充是实现细节，别依赖跨平台的布局。

## 二、体检报告比喻：四组信息

| 组 | 成员 | 能拿到的信息 |
| --- | --- | --- |
| 身份 | `st_dev` + `st_ino` | 文件系统的"街道 + 门牌号"，全局唯一 |
| 类型与权限 | `st_mode` | 目录还是普通文件？谁能读谁可写？ |
| 户口 | `st_uid` / `st_gid` / `st_nlink` | 属主用户 / 组、几个硬连接 |
| 体格与时间 | `st_size` / `st_mtim` 等 | 多大、上次修改何时 |

`st_mode` 把"类型"塞在高位、"权限"塞在低位，一个整数干两件事（如 `0100644` = 普通文件 + `rw-r--r--`）；拆卸方法见 [[课程笔记/C语言/系统接口/S_ISDIR与S_ISREG-位掩码宏与mode_t|S_ISDIR 与 S_ISREG 笔记]]。

## 三、谁填表：stat 函数家族

| 函数 | 作用 | 差异 |
| --- | --- | --- |
| `stat(path, &st)` | 按路径查 | **会跟随符号链接** |
| `lstat(path, &st)` | 按路径查 | 不跟随，汇报链接本身 |
| `fstat(fd, &st)` | 按已打开的文件描述符查 | 适合已在读写的文件 |
| `fstatat(dirfd, path, &st, flags)` | 相对某个目录 fd 查 | 可加 `AT_SYMLINK_NOFOLLOW` |

返回约定：**成功 0，失败 -1 并写 `errno`**。

**输出参数惯用法**：C 函数只有一个返回值，想"吐出"整个结构体就传地址让函数填：

```c
struct stat st;              /* 准备一张空表（栈上） */
if (stat(child, &st) != 0)   /* 把表的地址交给系统去填 */
{ perror(child); continue; }
```

## 四、`if (stat(...) != 0)` 精讲

**为什么是 `!= 0`**：POSIX / Unix 约定"**0 = 没出事，非 0 = 失败**"（`stat` 具体返回 -1）。所以读作"出错了吗"。写 `!= 0` 比省略成 `if (stat(...))` 更明确：比较对象是错误码。

**为什么必须"先判后看"**：`struct stat st;` 是栈上**未初始化**的；只有返回 0 时系统才保证填好，失败时内容未指定。顺序不能倒：

```c
if (S_ISDIR(st.st_mode))     /* ❌ 危险：还没确认查询成功就读 st，可能是垃圾 */
if (stat(child, &st) != 0)   /* ✅ 先拿"填表成功"的收据，再信任表 */
```

**失败分支的处理**：`perror(child)` 报出"是哪个路径出的问题"（`errno` 由刚失败的 `stat` 写入，必须紧跟）；`continue` 而不是 `return 1`——这是"几百个条目里的一个"，不是"整个目录打不开"。典型失败场景：断掉的符号链接、没权限、**TOCTOU 竞态**（`readdir` 列出来后、`stat` 之前文件恰好被删）。对比 note-stats.c:21-26：顶层目录打不开 `return 1`，单条目出问题 `continue`——错误处理按层级分档。

## 五、什么时候用它

1. **判断路径类型**：递归前分清"目录（进去）"与"普通文件（处理）"——note-stats.c:44-51；
2. **不打开文件就取元数据**：大小、修改时间、属主、权限（不需要文件的读权限，只需路径上各目录的执行权限）；
3. **实现 `ls` / `find` / 备份 / 同步**：比较 `st_mtim` 判断新旧；比较 `st_dev` + `st_ino` 判断两个路径是否同一文件、防重复遍历；
4. **为何不用 `readdir` 的 `d_type` 省掉 `stat`**：`d_type` 可能是 `DT_UNKNOWN`，不可信；`stat` 是权威答案。

> 两个进阶注意：① 用 `stat` 时目录的符号链接会被跟随递归，链接成环会无限深入——健壮工具记录已访问的 `st_dev` + `st_ino` 防重，本工具未做防护（信任输入环境的简化）；② 冷知识：目录的 `st_nlink` = 2 + 直接子目录个数（每个子目录的 `..` 都指向它），与 [[课程笔记/C语言/系统接口/点与点点-必须跳过的两个目录条目|点与点点]]闭环。

## 术语小词典

| 词 | 大白话 |
| --- | --- |
| 元数据（metadata） | "关于数据的数据"——大小、时间、属主等，不含内容 |
| `st_mode` | 打包了文件类型 + 权限的位模式整数 |
| 输出参数 | 传地址进去、让函数填充的变量（如 `&st`） |
| `lstat` vs `stat` | 前者不跟踪符号链接，汇报链接自己 |
| TOCTOU | "检查时还在，使用时没了"的时间窗竞态 |
| 错误处理策略 | 顶层失败中止（return）、条目失败跳过（continue） |

## 自测

> [!question]- 想好再点开
> 1. 为什么不能先写 `if (S_ISDIR(st.st_mode))`、把 `stat` 调用放到后面？
>    答：`st` 未初始化；只有 `stat` 返回 0 才保证填好，失败时内容未指定，先读就是拿垃圾数据做判断。
> 2. 假如把失败分支的 `continue` 改成 `return 1`，遍历含 100 个子文件夹的目录、第 3 个条目恰好奇坏时会发生什么？
>    答：整个遍历当场中止，剩下 97 个条目全被跳过、结果不完整；这是"条目级失败"被误当成"目录级失败"。
> 3. `stat`（跟随链接）与 `lstat`（不跟随）的选择，在与 `S_ISLNK` 配合时有什么差别？
>    答：`stat` 报告链接目标的类型（指向普通文件就报普通文件）；`lstat` 报告"这是个链接"，若代码跳 `S_ISLNK` 就不会深入链接。

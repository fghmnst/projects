# 点与点点：必须跳过的两个目录条目（新手版）

> [!note] 一句话先行
> 每个目录里都真实存在 `.`（当前目录）和 `..`（上级目录）这两个条目；递归遍历若不跳过，`.` 会让函数对自己无限递归、`..` 会把遍历带回上一层——程序轻则打转、重则爆栈崩溃。note-stats.c:31-34 的两连判断就是为此。
> 相关：[[课程笔记/C语言/C语言|C语言]] · [[课程笔记/C语言/系统接口/struct-dirent-字段与readdir公共缓冲|struct dirent]] · [[课程笔记/C语言/项目实战/目录遍历与递归-note-stats步骤2|目录遍历与递归]]

## 一、那行代码的意图：只跳过两个"幽灵条目"

```c
if (strcmp(entry->d_name, ".") == 0 || strcmp(entry->d_name, "..") == 0)
{
    continue;   /* 本轮作废，直接去拿下一张卡片 */
}
```

- `strcmp(a, b)`：逐字符比较，**完全一样返回 0**。所以 `strcmp(名字, ".") == 0` 读作"这个名字恰好就是 `.`"；
- `||`：左右任一为真即可；`==` 优先级高于 `||`，不用加括号；
- `continue`：不是 `break`（跳出循环），而是**放弃本轮剩余代码、回到 `while` 条件再取一条**——命中的条目被静默跳过：不拼路径、不 `stat`、不递归。

## 二、不跳的后果：电梯在两楼层之间来回坐

关键事实：`readdir` 会把 `.` 和 `..` 当普通条目返回，而它们恰好都是"目录"：

```
扫描 projects/，取到 "."
child = "projects/."            ← 拼出来的路径，还是 projects 自己
stat 一看：是目录 → scan_dir("projects/.")
    → 又读到 "." → 拼出 "projects/./." → 又递归……
```

结果就是**无限递归**，一层套一层直到栈撑爆、程序崩溃。`..` 同理：它指向父目录，会把遍历"向上"带回已经扫过的地方，来回打转。

比喻：你在爬楼梯清点房间，`.` 是"本楼层"按钮，`..` 是"上一层"按钮；不把这两个按钮从清单里划掉，你就会永远坐电梯。

## 三、`.` 和 `..` 到底是什么

它们是**文件系统创建目录时自动生成的两个真实条目**（不是软件障眼法）：

| 条目 | 含义 | 指向 |
| --- | --- | --- |
| `.` | 当前目录自己 | 本目录的 inode |
| `..` | 父目录 | 上一层的 inode |

- **根目录特例**：`/` 的 `..` 指向它自己——"根的上一层还是根"；
- 它们是目录天然自带的**硬连接**：`. ` 是目录对自己 inode 的链接，`..` 是对父目录 inode 的链接。

## 四、日常作用（它们不是"杂物"）

- **构成相对路径**：`../obsidian` 先上一层再进 `obsidian`；`./note-stats` 表示"当前目录下的程序"。因为安全原因，当前目录默认不在 `PATH` 里，所以运行本目录的程序必须写 `./`；
- **导航与命令**：`cd ..` 上一层、`cd .` 原地不动；`cp ../file .` 拷到当前目录；`mv a ../b`；
- **`ls -a` 才能看到它们**：`ls` 默认藏起所有以 `.` 开头的条目——这就是"隐藏文件 / 点文件"约定的来源（`.gitignore`、`.env`、本仓库的 `.hermes.md`）。

## 五、别把"点文件"和这两个特殊条目混为一谈

- `.` / `..` 是**目录结构条目**，只有这两个名字特殊；
- 点文件（`.gitignore` 等）是**普通文件**，只是显示约定为隐藏；
- 所以跳过条件**不能偷懒写成 `d_name[0] == '.'`**——那会把 `.hermes.md` 这类正经的 `.md` 文件也误伤。note-stats 的精确两连判断，正是为了"只躲幽灵，不误伤点文件"。

## 术语小词典

| 词 | 大白话 |
| --- | --- |
| 硬连接（hard link） | 一个 inode 被多个名字指向；`.` / `..` 是目录天然自带的两个 |
| inode | 文件在文件系统里的"身份证"（编号 + 元数据） |
| 点文件（dotfile） | 名字以 `.` 开头、约定隐藏的普通文件 |
| 短路求值 | `\|\|` 左边为真就不再算右边 |
| 无限递归 | 函数直接 / 间接调用自己没有终止条件，直至栈溢出 |

## 自测

> [!question]- 想好再点开
> 1. `continue` 和 `break` 在这段里各会带来什么不同后果？
>    答：`continue` 只放弃本轮、继续读下一个条目（正是需要的）；`break` 会直接结束整个遍历循环，漏掉后面的文件。
> 2. 为什么写 `d_name[0] == '.'` 作为跳过条件，会漏掉仓库里的 `.hermes.md`？
>    答：它会把**所有**点开头名字都跳过，而 `.hermes.md` 是正经的 `.md` 文件；应只精确跳过 `.` 和 `..` 两个名字。
> 3. 仅跳过 `.`、不跳过 `..`，程序会怎样？
>    答：`.` 的无限递归解决了，但 `..` 会带你回上级目录，来回打转（向上再向下），依旧无法正常结束。
